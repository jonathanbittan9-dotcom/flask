The cascade and specificity

This paragraph is inside #showcase — id-level specificity (1,0,1) wins over the .card p rule (0,1,1) and the bare p rule (0,0,1) both. It's also DIRECTLY targeted by #showcase .literal-p, which is why it isn't the inherited teal from #showcase's own color.

This paragraph is inside a plain .card — .card p (0,1,1) wins here, over the bare p rule (0,0,1).

This one has class="demo-note" — both demo-note rules tie at 0,1,0, so the one written LAST in the <style> block wins (grey, not orange).

This text is forced red by !important. Uncomment the rule right below it in the <style> block, reload, and watch it stay red anyway — that's the trap: the only way to override an !important rule normally is with ANOTHER !important, which is how stylesheets spiral out of control.

Three things to check before reaching for !important

  1. Open DevTools, inspect the element, and read the Styles panel — a crossed-out rule shows you exactly what overrode it and where.
  2. Check the selector actually matches: right class, right element, no typo.
  3. Check for an unclosed brace in a rule ABOVE the one you're debugging — it can silently disable everything after it (lesson 1).
